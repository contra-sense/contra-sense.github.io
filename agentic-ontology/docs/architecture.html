      #构建与交付

      授权资料
  → 证据准入
  → SemanticProposal
  → 验证与审核
  → KnowledgeRevision
  ├→ 3D 本体图谱 → 人类审阅
  └→ CognitivePackageDraft → A3S Use generation → A3S Code / Agent

      #Domain model

      • Workspace：组织知识、授权和本体版本的隔离权威。
      • KnowledgeScope：允许进入一次构建的资料、版本与处理边界。
      • Evidence：经准入、可引用的资料证据。
      • SemanticProposal：Agent 提出的候选概念、关系或陈述。
      • KnowledgeRevision：人工批准后编译、带精确 parent 的不可变知识修订。
      • CognitivePackageDraft：包含 OKF、Skill 等表面的 schema-v3 候选；本体语义绑定精确 activated revision。
      • Package generation：由 A3S Use 安装、锁定并发布、供 Agent 使用的精确版本。

      3D 图谱是 KnowledgeRevision 的人类审阅投影，不是 Agent 查询接口。

      Rust 引擎会把每个 LearningProject、ResourceSet 和已准入来源绑定到一个 Organization、Workspace 授权策略 generation 与不可变 KnowledgeScope revision。 来源白名单、允许格式和预算都会在读取前校验。每个精确 scope revision 现在也有一个按摘要寻址的持久化来源 inventory：单调序列的 observation 会确定性地对账为不可变版本或删除墓碑，冲突不会覆盖原快照。每次构建现在都会把该 完整快照与显式声明来源的精确版本冻结进项目意图、准入过程和包来源记录。来源已删除、内容变更或 resolver 漂移时，构建会在解析前被直接拒绝。每个逻辑 scope 都有一个持久化、受 compare-and-swap 保护的 active scope revision；已配置的来源读取会持有共享 lease，并在打开来源内容前拒绝缺失、过期或已撤销的 revision。

      精确人工批准后，引擎会编译或复用不可变 KnowledgeRevision。它绑定冻结的 scope/inventory、来源与文档集合、有证据约束的 claim/concept/procedure/conflict、不含原文的证据 producer 身份、approval/report/policy 摘要、编译器 generation 与精确 parent；仅属于认知包的 Skill 指导不会进入本体权威。独立的 Workspace 级 head 通过精确 parent compare-and-swap 前进；对象先落盘，精确重放不增加 generation，损坏或竞争状态会 fail closed。

      CLI 会在激活前记录“来源版本 → 文档 → 证据 → revision → 绑定 revision 的 draft”依赖链，因此按来源或完整 scope 查询的摘要绑定影响集会覆盖批准后的 revision。激活回执随后把精确 revision 与审批材料封装为不可反序列化的编译输入；OKF 语义只来自 revision，revision identity 会写入 provenance 与 package 摘要。人工图谱与 A3S Use generation 的失效仍由各自权威组件完成，因此 v0.1 只声明 revision 到 package candidate 的权威链，不声明安装、锁定或发布 generation。

      Parser 证据还会绑定到已审阅 Parser generation 的精确生成能力矩阵。只有经资格约束的 DOCX、XLSX、PPTX、PDF 和图片条目才能进入语义投影；检测格式、媒体类型、自然 unit 漂移或不支持的旧格式都会 fail closed。provenance 保留矩阵摘要以及真实的结构化、视觉、调用方提供或 feature-gated 状态，不暴露 Parser 仓库路径。

      发布级保证保持独立。锁定的 policy 加上经过单独审阅的精确 receipt，必须完整覆盖五类 profile 以及通过的 provider、resume、Linux、macOS 与 Windows 证据；缺失、失败或不可用结果都会 fail closed。v0.1 不内置通过 receipt，因此不声称 Parser 已完成跨平台发布资格验证。

      模型输入使用 prompt-contract v2：固定的 system、task、schema 与 envelope 指令共享一个记录摘要；context 和 evidence 是带长度与 SHA-256 的 JSON，framing delimiter 会被转义。locale 不能增加 prompt 行，闭合 proposal 也不能增加 Tool、permission、package 或 approval 权限。

      解码后的语义值会在评估前重新构造：稳定 ID 必须与 map key 一致，关系必须引用已准入证据；自环或悬空关系、重复冲突以及非规范的有界字段都会 fail closed。

      #A3S 组件边界

      组件作用不拥有
      A3S Use校验认知包、解析依赖、安装、锁定并发布 generation生成或审核本体
      A3S Code运行 Ontology Agents，并承载消费精确 generation 的业务 Agent直接读取 3D 图谱
      A3S Flow保存探索、摄取、编译和评估的持久流程历史知识权威
      A3S Cloud部署角色、节点、路由、Secret 与 Runtime TaskKnowledgeScope 与本体版本

      #Quality

      质量目标包括引用完整性、授权正确性、修订与 package generation 可复现、语言和版本文档对等，以及公开产物不泄露实现细节。
