    #每个项目都有一份版本化的代码记忆

    Reviewer 为活跃项目维护内部知识图谱。它从 Rust symbols、Markdown sections 和受支持的 lat.md/ wiki links 提取节点与边，并将证据绑定到 exact ProjectVersion。

    #为什么不是每次都重写文档

    自动知识 refresh 首先是只读 derived projection。扫描结果写入 Reviewer 自己的 SQLite，不修改 repository，因此后台 refresh 不会制造 worktree noise，也不会和 Codex 的真实修改混在一起。

    物化是另一个明确能力。host 对 exact composed head 生成 deterministic Markdown、完整 bytes digest 与 add-only diff，作为 MaterializeKnowledgeGraph 进入普通 Approval Saga。创建 proposal 不写文件；只有批准后的 Project actor 才能在 lat.md/agentic-reviewer/ 下新增一个 content-addressed snapshot。

    #三种身份

    #Revision

    Revision 是某个 ProjectVersion 的内容寻址不可变图。相同内容重用相同 identity。A 到 B 再回到 A 时，current head 会回到已有 A revision，不复制历史。

    #Directed transition

    Transition 描述前一 revision 到当前 revision 的有向变化。A 到 B 与 C 到 B 到达相同内容，但 incoming evidence 不同，因此拥有不同 transition identity。

    每个 transition 记录 bounded file changes、previous 与 current one hop impact neighborhoods，以及 deterministic stale node repair proof。

    #Semantic overlay

    Knowledge Curator 只能产生 evidence bound Candidate。host validator 会重新加载 exact source revision 和 transition，验证节点、边、来源与预算后，才可能发布 semantic overlay。

    Overlay 不修改 source graph identity。composed query 在一个 A3S ORM read 中同时捕获 source head、incoming change head 与 semantic head，避免跨版本拼接。

    #自动刷新时机

    两条信号共同工作：

    1. daemon 默认每 30 秒检查 active project working directory。
    2. 一个成功 managed turn 会发出 metadata only refresh hint。

    hint 经过默认 3 秒 quiet period 合并。worker 捕获 exact ProjectVersion 后创建 version affine job，租约与 retry policy 都绑定这个版本。扫描期间 Project 变化会使 publication 失败关闭。

    #增量但不牺牲正确性

    scanner 使用 verified manifest、journal assisted discovery 与 dependency keyed Markdown fragment reuse 降低重复工作。同时保留这些保护：

    • 全局 Markdown invalidation 需要时强制 relink。
    • prepared bytes 只存在 refresh future 内，不进入 durable job。
    • 完整 project identity 与 version 在 publication 前再次检查。
    • node、edge、diagnostic 与 evidence 都有 domain owned budget。
    • normalized rows 与 canonical JSON 必须一致。

    #CLI 查询

    cargo run -p agentic-reviewer-cli -- knowledge refresh .
cargo run -p agentic-reviewer-cli -- knowledge read --project project:...
cargo run -p agentic-reviewer-cli -- knowledge search \
  --project project:... \
  "approval orchestrator" \
  --limit 20

    search 在一个 coherent snapshot 中读取有界的 source 与 exact-compatible semantic title/summary，并标记每个 hit 的 layer，不把任意查询交给模型。

    #审批后物化

    本地调用只提供 Project、requester、quorum 与 TTL，不能指定目标路径、target version、diff 或 bytes：

    cargo run -p agentic-reviewer-cli -- knowledge materialize \
  --project project:... \
  --principal principal:...

    返回值是 pending AR-* 或 already_materialized。批准后仍会重新检查 exact Project identity、ProjectVersion、source/change/semantic heads 与 immutable plan。目标路径的任何祖先 symlink、冲突对象或期间发生的 source change 都会失败关闭。publication 使用同目录 hard link 的 no replace 语义，不覆盖也不删除用户文件；gateway ACK 只进入 Verifying，host 观察到 exact path 与 digest 后才是 Succeeded。

    scanner 排除 Reviewer 管理的输出目录，避免下一次 refresh 递归索引自己的物化 snapshot。

    #自动 proposal 时机

    默认不自动创建物化审批。只有设置一个已经存在且有 proposal 权限的显式 requester 后才启用：

    AGENTIC_REVIEWER_KNOWLEDGE_MATERIALIZATION_REQUESTER_ID=principal:... \
cargo run -p agentic-reviewer-daemon

    没有 Knowledge Curator 时，settled deterministic refresh 会 reconcile proposal。有 Curator 时，系统等待 host semantic publication 或 reconciliation 完成；Curator terminal failure 会退回 deterministic composed head。correlation 来自 exact heads，因此 restart 与重复 reconciliation 不会为同一内容创建多个审批。这个 automation 只有 proposal port，没有 dispatch 或 filesystem authority。

    #可选 Knowledge Curator

    Knowledge Curator 默认关闭，使用独立 provider、model、Keychain reference 与 job queue：

    AGENTIC_REVIEWER_ENABLE_KNOWLEDGE_CURATOR=true \
AGENTIC_REVIEWER_KNOWLEDGE_CURATOR_PROVIDER=openai \
AGENTIC_REVIEWER_KNOWLEDGE_CURATOR_MODEL=your-model-id \
AGENTIC_REVIEWER_KNOWLEDGE_CURATOR_API_KEY_REF=cognition:knowledge-curator-api-key \
cargo run -p agentic-reviewer-daemon

    这个 agent 没有工具，也没有 publish、approve、dispatch、worktree write、Codex 或 messaging authority。它只能对 host 提供的 evidence envelope 返回 Candidate。
