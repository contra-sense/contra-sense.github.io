    #自动化可以前进，权限不能自行生长

    Agentic Reviewer 的核心不变量很简单：读取和建议可以自动发生，机器变更必须绑定一个明确的人类决定，并且最终结果必须由目标侧证据证明。

    #五个相互独立的边界

    边界能做什么不能做什么
    Observation发现同用户进程，读取 Reviewer 自有投影把发现解释成管理权限
    Cognition生成 finding 或 Candidate审批、dispatch、直接写工作树
    Approval记录 principal 对 exact digest 的决定改写动作内容或目标版本
    Gateway消费一次性 permit 并调用一个固定 mutation扩展到未挂载的 mutation family
    Verification读取目标侧终态并形成 proof根据日志提示或 ACK 猜测成功

    这五层通过 application ports 连接。任何 adapter 都不能绕过 use case 直接协作。

    #Approval Saga 绑定什么

    一个 ProposedAction 至少绑定：

    • 请求 principal
    • exact mutation family
    • exact instance、thread 与 turn
    • runtime revision
    • 可用时的 Git head 与 worktree digest
    • 创建与过期时间
    • canonical action digest

    审批记录引用该 digest 与 target version。审批后目标变化，动作进入 stale，不会被偷偷重算成一个新动作继续执行。

    #状态不是装饰

    Approval aggregate 使用显式状态机：

    pending
  -> approved | rejected | expired
approved
  -> revalidating
revalidating
  -> stale | admitted
admitted
  -> dispatching
dispatching
  -> verifying | unknown | failed
verifying
  -> succeeded | failed | stale | unknown

    unknown 是保守终态。网络写入可能已经发生但响应丢失时，系统不会自动重试并制造第二次 mutation。

    #ACK 为什么不是成功

    网关响应只能证明通信层观察到某件事，不能证明目标状态已经改变。

    以 managed turn interrupt 为例：

    1. actor 消费 exact permit 并发送 turn/interrupt。
    2. 成功 ACK 只让动作进入 verifying。
    3. 只读 verifier 查询 exact thread 与 turn。
    4. 只有该 turn 的终态是 interrupted 才形成成功 proof。
    5. inconclusive observation 不写入结论，持久 job 稍后再次检查。

    #PID 不能单独表示目标

    操作系统会复用 PID。Reviewer 用 machine boot time、PID 与 process start time 组成稳定 instance identity。针对操作系统进程的 mutation 必须重新校验完整 identity，不能只凭一个整数。

    当前 OS termination gateway 还把最后一步绑定到不可复用的 kernel capability。Linux 使用 pidfd，macOS 使用含 pidversion 的 audit token，并在同一次 gateway call 内完成 metadata observation、capability revalidation 与一次性 SIGTERM。其他平台明确返回 unsupported，不会退化成先检查再 kill(pid) 的竞态实现。signal accepted 仍不是成功；只读 verifier 必须证明 exact instance 已退出。

    #IM 不是第二条权限通道

    微信、Telegram 或未来 IM 只承载命令和决定。系统会在同一持久事务中重新验证：

    • account 与 conversation binding 仍 enabled
    • sender 映射到 exact principal
    • principal role 满足动作策略
    • inbox message 尚未被消费
    • approval、target 与 runtime revision 仍匹配

    模糊表达不能产生安全决定。当前文本 fallback 只接受精确语法，例如：

    批准 AR-7F30AB19
拒绝 AR-7F30AB19

    #默认关闭的数据披露

    A3S Reviewer 的默认 evidence policy 是 metadata。以下披露分别控制，不能互相推导：

    1. Project habits 允许发送当前 thread 对应 Project 与 Global 的 active preference text。
    2. Project knowledge 允许发送有界、验证过的 immutable graph summary。
    3. Project transitions 允许发送有界 changed path、impact neighborhood 与 repair metadata，并要求同时开启 Project knowledge。

    原始 transcript、完整源文件、absolute project root、Git diff、token 与 credentials 不属于默认 context。

    #当前明确不做的事

    • 不注入任意进程内存、PTY 或 stdin。
    • 不替代 Codex 自身推理与工具 runtime。
    • 不让 cognition agent 直接编辑 repository。
    • 不把 model generated knowledge 当作 source truth。
    • 不在 shutdown 或恢复期间补做审批或猜测结果。

    这些限制让自动化程度低于“万能接管器”，也让每一次控制行为都有可解释边界。
