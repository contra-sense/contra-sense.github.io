    #IM 是控制面入口，不是隐形管理员

    Agentic Reviewer 允许 verified user 从微信或 Telegram 查询整台机器的 Codex 状态、查看 findings 和 approvals，并提交精确决定。channel adapter 没有数据库、cognition、fleet mutation 或 verification 能力。

    #当前 WeChat / Weixin 兼容范围

    内置 channel-weixin 实现 Tencent 通过 OpenClaw Weixin connector 公开协议中当前可保证的子集：

    • QR login 与 status polling
    • getupdates
    • text sendmessage

    getconfig、typing、media 和 interactive actions 当前不对外承诺。协议版本显式固定，并用脱敏 fixtures 覆盖，不把外部接口当作永远稳定的 SDK。

    #首次扫码

    cargo run -p agentic-reviewer-cli -- channel connect weixin \
  --owner-name "Your name"

    首次 pairing 可以 bootstrap 一个本地 Owner。已有 Owner 为新 binding 授权时，显式传入 principal：

    cargo run -p agentic-reviewer-cli -- channel connect weixin \
  --principal principal:... \
  --owner-name "Second device"

    随后读取并推进 durable pairing：

    cargo run -p agentic-reviewer-cli -- channel pairing read --pairing pairing:...
cargo run -p agentic-reviewer-cli -- channel pairing advance --pairing pairing:...

    若 provider 要求数字验证，增加 --code 1234。QR 内容保持 ephemeral，confirmed token 写入 Keychain。

    #Telegram Bot API 私聊配对

    Telegram 使用 BotFather token。token 只能先写入 channel 专用 Keychain service，不放进环境变量的 value、命令参数、SQLite 或日志：

    security add-generic-password \
  -U \
  -s dev.contra-sense.agentic-reviewer.channel \
  -a channel-bootstrap:telegram-bot \
  -w

    daemon 只接收非秘密 reference：

    AGENTIC_REVIEWER_TELEGRAM_BOT_TOKEN_REF=channel-bootstrap:telegram-bot \
cargo run -p agentic-reviewer-daemon

    开始 pairing：

    cargo run -p agentic-reviewer-cli -- channel connect telegram \
  --owner-name "Your name"

cargo run -p agentic-reviewer-cli -- channel pairing advance \
  --pairing pairing:...

    返回的 QR 是五分钟有效的 https://t.me/<bot>?start=ar_<nonce> deep link。connector 只接受 exact /start ar_<nonce> 私聊，且 sender ID 必须等于 private chat ID。群聊、频道、bot sender、media-only message、错误 nonce 和 trailing text 都不能创建 binding。

    connector 会先用更高 offset 明确确认 matching /start，再创建本地 account，避免配对 secret 被新 inbox worker 重放。确认响应不明确时保留已匹配 scanner，下一次 advance 必须先完成 offset 确认。

    连接后 daemon 使用 durable Telegram update cursor 进行 long polling，只把 private text 送入统一 inbox；canonical ar_ pairing command 会在持久化前丢弃，避免 nonce 落入 SQLite。被忽略的 group/media update 仍推进 cursor，避免无限重放。回复 message ID 经现有 reply-context Keychain 路径保存；发送 timeout、HTTP 5xx 或成功响应损坏进入 unknown，不会因 Telegram 缺少 idempotency key 而重试。

    #实时查询命令

    命令结果
    /status读取 privacy reduced Fleet 状态
    /refresh触发一次 OS discovery 后返回 Fleet
    /codex列出 Reviewer 自有 managed connections
    /threads <connection-id>查询 bounded thread projections
    /turns <connection-id>查询 bounded turn projections
    /requests <connection-id>查询 observed pending requests
    /findings列出最近 findings
    /findings <connection-id>按 managed connection 过滤 findings
    /approvals列出可见 Approval Saga
    /approval AR-XXXXXXXX读取 exact action 与 lifecycle
    /habits列出 durable habit claims
    /knowledge materialize project:<32 hex>只为 exact current composed graph 创建物化审批

    这些命令先经过 deterministic parser，不调用 Control Agent。

    #精确审批语法

    普通 Approval Saga：

    批准 AR-7F30AB19
拒绝 AR-7F30AB19

    Codex 自身 observed request：

    允许 CR-0123456789abcdef0123456789abcdef
拒绝 CR-0123456789abcdef0123456789abcdef

    parser 对大小写、ID 长度、空格和 trailing text 都进行严格检查。同意一下 或 帮我批准 仍是普通 conversation，不会产生安全决定。

    knowledge command 同样是 exact grammar。它只创建 Approval Saga，不能选择 output path、bytes、diff 或 target version，也不会在处理 IM message 时直接写 worktree。真正写入发生在后续独立 Project actor；Stale、Verifying、Unknown、Succeeded 或 Failed 会回到实际批准动作的同一个 verified conversation。

    #Finding 与 habit 管理

    /finding acknowledge review-finding:<digest>
/finding dismiss review-finding:<digest>
/finding reopen review-finding:<digest>

/habit set language:rust testing.before-handoff Run all tests.
/habit show habit:<digest>
/habit confirm habit:<digest>
/habit suspend habit:<digest>
/habit forget habit:<digest>

    每个 authoritative command 会在 A3S ORM transaction 内重新检查 binding、role、inbox ownership 与 canonical aggregate。

    #主动通知必须订阅

    /subscribe findings
/unsubscribe findings
/subscribe approvals
/unsubscribe approvals
/subscriptions

    Reviewer 不默认广播 findings 或 Codex approval prompts。subscription 绑定 principal、channel account 与 conversation route，delivery 使用 transactional outbox。ambiguous send 进入 unknown，不会假装成功。

    #普通聊天与 Control Agent

    默认情况下，不匹配精确命令的文本只会保留为 conversation input，不会触发 provider。可选 Control Agent 默认关闭，因为它会把 bounded raw IM text 发送给独立 A3S Code provider：

    AGENTIC_REVIEWER_ENABLE_CONTROL_AGENT=true \
AGENTIC_REVIEWER_CONTROL_AGENT_PROVIDER=openai \
AGENTIC_REVIEWER_CONTROL_AGENT_MODEL=your-model-id \
AGENTIC_REVIEWER_CONTROL_AGENT_API_KEY_REF=cognition:control-agent-api-key \
cargo run -p agentic-reviewer-daemon

    Control Agent 只有只读 query candidate 与 selector only proposal candidate 类型。host 负责补全 hidden identity，所有 mutation proposal 仍必须进入 Approval Saga。

    #当前运行时 connector 扩展点

    daemon 使用按 ChannelId 索引的 ChannelConnectorRegistry。每个 adapter 注册 descriptor 一致的 pairing port 与 messaging port；duplicate ID 会在 startup 失败。channel/list、pairing RPC、restart recovery、connected account supervisor、receive 与 delivery 都通过 registry 解析，不包含 Weixin 或 Telegram concrete branch。

    当前生产 composition 同时注册 Weixin 与 Telegram。两个 adapter 共享 principal、command、approval、inbox、outbox 和 lifecycle domain，但各自封装 pairing、receive、delivery、cursor 与 transport ambiguity。

    #后续 out of process IM 如何接入

    核心不使用 Rust dynamic library 作为 plugin ABI。第三方 connector 计划以 supervised child process 运行，通过私有 Unix socket 上的 versioned JSON RPC 实现最小协议：

    initialize
account/list
account/connect
message/send
message/received
delivery/updated
health/read
shutdown

    新 connector 只负责 pairing、receiving、rendering 与 delivery。principal、approval、query、outbox 和 audit 仍由 Reviewer 核心拥有，因此增加 Feishu、Slack 或 Web channel 不需要修改 domain。
