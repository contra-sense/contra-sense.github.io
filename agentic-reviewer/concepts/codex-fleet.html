    #看见所有进程，不等于控制所有进程

    Fleet Manager 周期性观察同用户 Codex 进程，并把 PID 复用安全的 instance identity 持久化为查询投影。控制权来自受监督连接，不来自进程发现。

    #四种 control level

    Level含义
    managedexact Codex client 连接 Reviewer 自有、版本固定的 App Server endpoint
    observedReviewer 能安全识别并报告该同用户进程，但没有 mutation transport
    unmanaged识别为 Codex 相关进程，但不满足受支持管理条件
    disconnected曾有管理或观察关系，当前连接已经断开

    进程状态另外表示为 starting、idle、running、waiting_approval、failed、disconnected 或 exited。control level 与 process state 是两条不同轴。

    #发现周期

    daemon 默认每 5 秒执行一次 OS observation。CLI 可以立即触发：

    cargo run -p agentic-reviewer-cli -- fleet refresh

    读取当前与历史记录：

    cargo run -p agentic-reviewer-cli -- fleet list
cargo run -p agentic-reviewer-cli -- fleet status --pid 12345
cargo run -p agentic-reviewer-cli -- fleet status --instance os:...

    fleet list 包含已退出历史，使重启、PID 复用与连接代际变化仍可审计。

    #managed 拓扑

    daemon 拥有一个私有 WebSocket over Unix App Server child。启动流程会：

    1. 精确检查 Codex CLI 版本，目前固定为 0.147.0。
    2. 在用户私有路径创建 endpoint。
    3. 完成 initialize handshake。
    4. 用同用户 PID 与启动身份再次验证 child。
    5. 只为该 connection generation 注册能力。

    reviewerctl codex launch 使用 Codex 官方 --remote unix://PATH 连接它：

    cargo run -p agentic-reviewer-cli -- codex endpoints
cargo run -p agentic-reviewer-cli -- codex launch --cd .

    已有 Codex 客户端不会被静默迁移到这个 endpoint。

    #可查询 projection

    cargo run -p agentic-reviewer-cli -- codex connections
cargo run -p agentic-reviewer-cli -- codex threads --connection codex-connection:... --limit 20
cargo run -p agentic-reviewer-cli -- codex turns --connection codex-connection:... --limit 20
cargo run -p agentic-reviewer-cli -- codex requests --connection codex-connection:... --limit 20

    这些查询读取 Reviewer 持久化、已脱敏的 bounded projection，不向通用 App Server JSON RPC 转发任意请求。

    #ObservedRequestsOnly

    Codex server request 订阅是 connection scoped。Reviewer 只能保证处理自己实际观察到的 pending request，不能声称截获了所有客户端看到的请求。

    连接中断时：

    • 不合成“漏掉的请求”。
    • 不估计 missed request count。
    • 旧 action 不能移动到新 connection generation。
    • 状态与 IM 文案必须明确呈现 observed request only 边界。

    #当前可执行能力

    生产 composition 当前只挂载受限路径：

    • 人类批准的 exact managed turn interrupt。
    • 对 Reviewer 实际观察到的 Codex approval request 提交 exact response。
    • 对 Reviewer 自有 App Server child 执行一次 connection-owned SIGTERM，并保留用户的 stop 意图。
    • 对 exact observed/unmanaged Codex instance 执行一次 identity-bound SIGTERM。

    managed termination 的 capability 在 child spawn 时取得，并由 supervisor 保管。registry 将它绑定到 exact connection generation、OsProcessRef 与 instance；最终 A3S ORM fence 重新校验 connection、process、eligible lifecycle 与审批时的 runtime revision，之后才消费一次 SIGTERM。session 关闭为 exited，不会立即启动 replacement。

    observed/unmanaged OS termination 同样必须经过 exact target version revalidation、durable claim 与 one-use attempt permit。Linux gateway 使用 pidfd，macOS gateway 使用含 pidversion 的 audit token，并在 metadata refresh 后重新校验同一实例；daemon 自身、非同用户、非 Codex、identity mismatch 与任何 thread/turn target 都在 signal 前拒绝。两条 termination 路径的成功 syscall 都只进入 verifying，exact process instance 真正消失后才能形成成功 proof。

    领域中仍可以表达 start 与 steer，但这些 mutation branch 没有挂载。类型存在不代表运行时授权存在。
