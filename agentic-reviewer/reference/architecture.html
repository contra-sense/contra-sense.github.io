    #一个本机控制平面，多个严格能力边界

    Agentic Reviewer 采用 Rust modular monolith。一个 reviewerd 进程组合 domain、application、adapters 与 workers，让本机事务、低延迟 observation 和 graceful shutdown 保持简单，同时用 crate 边界阻止权限扩散。

    完整设计与 62 个已写 ADR 位于仓库的 docs/ARCHITECTURE.md 与 docs/adr/。编号已经推进到 ADR 0073，中间编号保留给尚未单独落盘的早期决策。

    #第一性原理

    1. 机器变更比建议昂贵，必须有单独授权路径。
    2. 发现进程不能自动产生控制权。
    3. 模型输出是不可信 Candidate，不是 domain fact。
    4. 长期服务必须让 restart、duplicate delivery 与 ambiguous network write 成为正常状态。
    5. 外部协议会变化，Codex、Weixin 与未来 IM 类型不能进入 domain。
    6. 项目知识必须绑定 immutable source evidence，不能只靠自然语言记忆。

    #依赖方向

    domain <- application <- adapters / infrastructure <- daemon
    • domain 包含 entities、value objects、policies、state transitions 与 events。
    • application 包含 commands、queries、services、actors 与 port traits。
    • adapters 实现 Codex、A3S Code、channel、SQLite、Keychain 和 OS ports。
    • daemon 是唯一 composition root，负责创建 concrete implementations 与 shutdown ordering。

    adapter 之间不互相 import。跨 adapter 协作必须回到 application use case 或 domain event。

    #CQRS 与 audit journal

    系统分离三类数据：

    • Command 验证并推进 aggregate。
    • Query 读取 bounded denormalized projection。
    • Append only event journal 保存安全相关因果历史。

    这不是 full event sourcing。当前 operational state 保存在明确 tables 中，关键 transition 同时写 immutable events。这样既能高效查询，也能审计决定、identity、habit 与 intervention。

    #Per target actor

    每个 managed Codex target 有一个逻辑 actor。durable claim 绑定 exact admission revision，actor 串行化 revalidation、dispatch 与 verification，同时全局 semaphore 允许不同 target 并发。

    claim 不是执行事实。只有事务消费 live claim 并产生 non cloneable DispatchAttemptPermit 后，系统才跨过可能产生外部副作用的边界。崩溃发生在此之后时，recovery 使用 unknown，不会重放。

    #A3S ORM

    #为什么选择 A3S ORM

    这里需要的不只是把 row 映射成 struct。Approval Saga、outbox、leases、idempotency 与 compare and set 都要求事务语义在 async cancellation 与 restart 下保持可证明。

    A3S ORM 在 infrastructure adapter 内提供：

    • Tokio safe SQLite single connection executor
    • cancellation safe transactions
    • WAL、foreign key 与 bounded busy timeout defaults
    • ordered、SHA 256 checksummed atomic migrations
    • typed query 与 bounded batch execution
    • 适合 CAS、lease fencing 和 durable projection 的精确语义

    application 只依赖 repository ports，不依赖 A3S ORM type。未来更换 persistence adapter 不会改变 domain state machine。

    #它当然有迁移系统

    仓库当前包含 migrations/0001_initial.sql 到 migrations/0039_project_mutation_lifecycle_notifications.sql。A3S ORM 维护 a3s_orm_migrations version 与 checksum，按序原子应用迁移，并在已应用文件内容被修改时失败关闭。

    因此本项目没有自造第二套 migrator，也没有让 daemon 在运行时执行散落的 ad hoc DDL。

    #认知组件

    四类 cognition 使用不同配置和最低权限类型：

    组件输出默认状态
    Live Reviewerevidence bound finding candidates可选 provider，确定性 fallback 常开
    Knowledge Curatorsemantic delta Candidates关闭
    Habit Learnerinferred habit Candidates关闭
    Control Agentquery 或 mutation proposal Candidates关闭

    它们都没有 approval、dispatch、verification 或 worktree write port。

    #知识数据模型

    每个 Project 具有 immutable source revisions、directed change sets、stale node repair proofs 与 independent semantic overlay heads。composed query 在单个 A3S ORM read 中捕获并 revalidate 三个 heads，防止并发刷新把不同版本拼接在一起。

    物化是独立的 Project mutation。host 将 exact composed head 渲染为 immutable plan，只允许在 lat.md/agentic-reviewer/ 下新增 content addressed Markdown。计划、ProjectVersion、diff 与完整 bytes 一起审批；dedicated actor 使用 atomic no replace publish，host verifier 再核验 exact path 与 digest。自动 proposal 只有配置显式 requester 后才启用，永远不会猜测第一个 Owner。

    #Channel protocol

    内置 Weixin 与 Telegram 都只是 adapter，不是核心特例。domain 只认识 ChannelAccount、Binding、Pairing、Inbox、Outbox、Principal 与 NotificationRoute。daemon 已通过 ChannelConnectorRegistry 按 ChannelId 注册 pairing 与 messaging ports，RPC、restart recovery、account supervision、receive 与 delivery 都不依赖 provider concrete type。Telegram 使用 Keychain BotFather token 和 exact private deep-link nonce，群聊不能建立 binding；第三方 channel 后续演进为 supervised process 和 versioned JSON RPC，避免 Rust plugin ABI 不稳定性。

    #Shutdown ordering

    graceful shutdown 按权限由外到内收缩：

    1. 停止接收新 local 与 channel commands。
    2. 停止创建 proposals。
    3. 持久化或 expire pending delivery work。
    4. 取消 cognition jobs。
    5. 在 deadline 内 drain target actors。
    6. 关闭 App Server connections。
    7. flush outbox 与 audit writer。
    8. 关闭 SQLite。

    shutdown 期间不补做审批、不重试 ambiguous mutation，也不重新解释旧 action。
