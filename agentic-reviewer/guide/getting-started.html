    #先完成只读健康检查

    Agentic Reviewer 当前面向 macOS 本机开发。第一阶段不要开启任何模型或自动提案能力，只启动 daemon，并确认 health 与 fleet 查询能稳定工作。

    Reviewer 会发现同用户 Codex 进程，但不会接管任意现有进程。只有显式连接到 Reviewer 自有 App Server endpoint 的客户端才会进入 managed 控制级别。

    #前置条件

    项目当前要求
    操作系统macOS first，Linux adapter 已有边界但尚不是首要部署目标
    Rust1.88，仓库中的 rust-toolchain.toml 会固定工具链
    Codex CLImanaged App Server 路径精确固定为 0.147.0
    数据库本机 SQLite，由 A3S ORM 创建和迁移
    密钥可选认知能力使用 macOS Keychain，不从明文配置读取

    克隆并检查工作区：

    git clone https://github.com/contra-sense/agentic-reviewer.git
cd agentic-reviewer
cargo test --workspace

    #启动 daemon

    在第一个终端运行：

    cargo run -p agentic-reviewer-daemon

    默认情况下，daemon 会创建私有 Unix socket、打开 A3S ORM 管理的 SQLite 数据库、周期性观察同用户 Codex 进程，并启动确定性知识刷新与恢复任务。可选 A3S cognition 仍保持关闭。

    #完成第一成功动作

    在第二个终端依次执行：

    cargo run -p agentic-reviewer-cli -- health
cargo run -p agentic-reviewer-cli -- fleet refresh
cargo run -p agentic-reviewer-cli -- fleet list

    成功标准：

    1. health 能通过私有 socket 读取数据库与 daemon 状态。
    2. fleet refresh 完成一次操作系统观察。
    3. fleet list 将进程呈现为 managed、observed、unmanaged 或 disconnected，不会把发现等同于控制权。

    需要机器可读输出时增加全局参数：

    cargo run -p agentic-reviewer-cli -- --json fleet list

    #启动一个 managed Codex 客户端

    先确认 Reviewer 自有 App Server endpoint 已就绪：

    cargo run -p agentic-reviewer-cli -- codex endpoints

    再让 reviewerctl 用经过检查的 Codex 可执行文件替换自身：

    cargo run -p agentic-reviewer-cli -- codex launch --cd .

    也可以附带初始 prompt：

    cargo run -p agentic-reviewer-cli -- codex launch --cd . "Review the current changes"

    这条路径使用 Codex 官方 --remote unix://PATH 连接 Reviewer 自有的共享 App Server。普通外部 Codex 进程仍然只被观察。

    #刷新项目知识图谱

    cargo run -p agentic-reviewer-cli -- knowledge refresh .

    命令返回稳定 project_id 后，可以读取或搜索当前验证过的 revision：

    cargo run -p agentic-reviewer-cli -- knowledge read --project project:...
cargo run -p agentic-reviewer-cli -- knowledge search --project project:... "approval orchestrator"

    自动 refresh 只写 Reviewer 自己的 SQLite projection，不会改动项目工作树。lat.md/ 物化是另一个必须单独提案、审批、派发和终态核验的 mutation。

    #连接微信或 Telegram

    #微信扫码

    Reviewer 对接 Tencent 通过 OpenClaw Weixin connector 公开的兼容协议子集。当前保证 QR 登录与状态轮询、getupdates 和文本 sendmessage。

    cargo run -p agentic-reviewer-cli -- channel connect weixin \
  --owner-name "Your name"

    终端会输出一次性 QR。扫描后读取本地持久状态并主动推进一次 provider 轮询：

    cargo run -p agentic-reviewer-cli -- channel pairing read \
  --pairing pairing:...

cargo run -p agentic-reviewer-cli -- channel pairing advance \
  --pairing pairing:...

    如果微信展示数字验证码：

    cargo run -p agentic-reviewer-cli -- channel pairing advance \
  --pairing pairing:... \
  --code 1234

    扫码前 principal intent 已经固定，QR 内容保持短期有效，长期凭据进入 Keychain。详细命令见 IM 渠道。

    #Telegram 私聊 deep link

    先通过 BotFather 创建 bot，再将 token 写入 channel 专用 Keychain。下面命令会交互式提示 secret：

    security add-generic-password \
  -U \
  -s dev.contra-sense.agentic-reviewer.channel \
  -a channel-bootstrap:telegram-bot \
  -w

    带着非秘密 reference 重启 daemon：

    AGENTIC_REVIEWER_TELEGRAM_BOT_TOKEN_REF=channel-bootstrap:telegram-bot \
cargo run -p agentic-reviewer-daemon

    启动 pairing，扫描或打开返回的 Telegram deep link，然后推进一次：

    cargo run -p agentic-reviewer-cli -- channel connect telegram \
  --owner-name "Your name"

cargo run -p agentic-reviewer-cli -- channel pairing advance \
  --pairing pairing:...

    只有 exact nonce 的 private /start 能完成 binding，群聊消息不会进入控制 inbox。Telegram 与 Weixin 使用完全相同的后续查询、审批和 lifecycle notification 命令。

    #创建第一个知识物化审批

    使用 pairing 创建的 principal_id 为当前 composed graph 创建只读 proposal：

    cargo run -p agentic-reviewer-cli -- knowledge materialize \
  --project project:... \
  --principal principal:...

    此时项目目录仍未改变。通过 CLI 的 approval decide 或微信中的精确 批准 AR-XXXXXXXX 完成人类决定后，daemon 的独立 Project actor 才会尝试在 lat.md/agentic-reviewer/ 下新增 immutable snapshot。已有冲突、source 变化或 symlink 会让旧批准 stale 或 fail closed，不会覆盖用户文件。

    #可选启用 A3S Reviewer

    确定性失败审查不依赖远程模型。若要额外启用 proposal only 的 A3S Code 审查，先将 API key 写入专用 Keychain service：

    security add-generic-password \
  -U \
  -s dev.contra-sense.agentic-reviewer.cognition \
  -a cognition:reviewer-api-key \
  -w

    再设置非秘密配置并启动 daemon：

    AGENTIC_REVIEWER_LLM_PROVIDER=openai \
AGENTIC_REVIEWER_LLM_MODEL=your-model-id \
AGENTIC_REVIEWER_LLM_API_KEY_REF=cognition:reviewer-api-key \
cargo run -p agentic-reviewer-daemon

    默认 evidence policy 是 metadata。Project habits、Project knowledge 和 directed transitions 是三个独立披露开关，默认都关闭。不要为了方便一次性全部打开，先阅读 配置参考 中的出站数据边界。
